Purpose (هدف)

این سند مشخص می‌کند که هر ستون موجود در Concept Template دقیقاً چه معنایی دارد، چه نوع داده‌ای را می‌پذیرد، چگونه اعتبارسنجی می‌شود و چه نقشی در معماری TANDIL دارد.

این سند مرجع اصلی تمام توسعه‌دهندگان، اپراتورهای تولید دانش و موتور Import خواهد بود.

---

Standard Field Definition (تعریف استاندارد فیلدها)

در ادامه، هر فیلد Concept به‌صورت مستقل تعریف خواهد شد.

هر فیلد دارای مشخصات زیر است:

- Field ID (شناسه فیلد)
- Field Name (نام فیلد)
- Persian Name (نام فارسی)
- Purpose (هدف)
- Data Type (نوع داده)
- Required (اجباری / اختیاری)
- Validation Rules (قوانین اعتبارسنجی)
- Allowed Values (مقادیر مجاز)
- Example (نمونه صحیح)
- Invalid Example (نمونه نادرست)
- Used By (بخش‌های استفاده‌کننده در سیستم)
- Notes (توضیحات تکمیلی)

---

Change Policy (سیاست تغییر)

هیچ فیلدی بدون تصویب معماری پروژه حذف یا تغییر داده نمی‌شود.

افزودن فیلد جدید تنها از طریق نسخه جدید KPS مجاز است.

تمام تغییرات باید در Snapshot معماری ثبت شوند.
