CHAPTER_05 — QUESTION SYSTEM ARCHITECTURE

SECTION_03 — Question Bank

PART_03 — Question Template چیست؟

در معماری TANDIL، آنچه در Question Bank نگهداری می‌شود، معمولاً خودِ Question نهایی نیست.

بلکه Question Template (الگوی سؤال) است.

Question Template ساختار منطقی یک سؤال را تعریف می‌کند، در حالی که Question نهایی ممکن است برای هر کاربر، هر Context و هر زمان، به شکل متفاوتی ایجاد شود.

---

اصل بنیادین

Question Template سؤال نیست.

Question Template الگوی تولید سؤال است.

---

تعریف Question Template

«Question Template یک تعریف استاندارد از ساختار، هدف و ارتباطات معماری یک سؤال است که می‌تواند برای تولید یا انتخاب Questionهای مختلف مورد استفاده قرار گیرد.»

---

هدف Template

این مفهوم برای پاسخ به این پرسش طراحی شده است:

«به جای ذخیره هزاران سؤال مشابه، چگونه می‌توان یک ساختار مشترک ایجاد کرد؟»

---

تفاوت Template و Question

Question Template

- قابل استفاده مجدد
- مستقل از کاربر
- مستقل از Context
- مستقل از زمان

---

Question

- مخصوص یک تعامل مشخص
- وابسته به کاربر
- وابسته به Context
- وابسته به زمان

---

مثال

Template:

««در شرایطی که [Scenario] رخ دهد، درباره [Concept] چه تصمیمی می‌گیرید؟»»

Question تولیدشده برای یک کاربر:

««اگر همکار شما اشتباه خود را از شما پنهان کند، چه تصمیمی می‌گیرید؟»»

Question تولیدشده برای کاربر دیگر:

««اگر دوست شما حقیقت را از خانواده‌اش پنهان کند، چه تصمیمی می‌گیرید؟»»

Template یکسان است.

Questionها متفاوت هستند.

---

اجزای Template

هر Question Template معمولاً شامل موارد زیر است:

- ساختار سؤال
- Conceptهای وابسته
- نوع Question
- هدف
- راهبرد تعامل
- پارامترهای قابل جایگزینی
- قوانین اعتبارسنجی

---

پارامترهای قابل جایگزینی

Template می‌تواند دارای متغیرهایی باشد که هنگام تولید Question مقداردهی می‌شوند.

برای مثال:

- نام افراد
- مکان
- سناریو
- سطح دشواری
- Domain
- مثال

این قابلیت باعث شخصی‌سازی بدون تغییر ساختار منطقی می‌شود.

---

مزایای استفاده از Template

استفاده از Template باعث می‌شود:

- حجم Question Bank کاهش یابد.
- تولید Question آسان‌تر شود.
- شخصی‌سازی ساده‌تر گردد.
- نگهداری سیستم راحت‌تر شود.
- کیفیت سؤال‌ها یکنواخت باقی بماند.

---

نقش در Dynamic Question Generation

موتور تولید سؤال معمولاً از Templateها استفاده می‌کند.

بنابراین:

Dynamic Question Generation اغلب به معنی ساخت Question جدید از روی Templateهای موجود است، نه تولید کاملاً بدون الگو.

---

تفاوت با تولید آزاد

در تولید آزاد:

AI از ابتدا متن سؤال را می‌نویسد.

در معماری TANDIL:

AI ابتدا باید در چارچوب Template حرکت کند و تنها بخش‌های مجاز را تکمیل یا شخصی‌سازی نماید.

---

نقش در معماری

Question Template میان:

- Concept
- Question Engine
- Dynamic Question Generation

قرار دارد.

به همین دلیل، یکی از مهم‌ترین اجزای بانک سؤال محسوب می‌شود.

---

اصل معماری

بر اساس قانون اساسی TANDIL:

Question Bank باید الگوهای استاندارد Question را نگهداری کند و Question Engine موظف است Questionهای نهایی را با استفاده از این Templateها و متناسب با وضعیت واقعی کاربر تولید یا انتخاب نماید.

این اصل تضمین می‌کند که سؤال‌های TANDIL همواره از یک معماری واحد پیروی کنند، در عین آنکه برای هر انسان، تجربه‌ای منحصربه‌فرد ایجاد شود.
