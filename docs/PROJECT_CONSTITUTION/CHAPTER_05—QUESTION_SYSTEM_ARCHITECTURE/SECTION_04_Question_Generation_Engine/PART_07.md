CHAPTER_05 — QUESTION SYSTEM ARCHITECTURE

SECTION_04 — Question Generation Engine

PART_07 — ثبت Question تولیدشده (Question Registration)

پس از آنکه یک Question تولید و اعتبارسنجی شد، هنوز یک مرحله مهم باقی مانده است.

سیستم باید بتواند این Question را در آینده:

- شناسایی کند،
- تحلیل کند،
- بازسازی کند،
- و به پاسخ کاربر متصل نماید.

به همین دلیل، هر Question تولیدشده باید پیش از نمایش، به‌صورت رسمی در سیستم ثبت شود.

---

اصل بنیادین

Question بدون شناسه، وجود معماری ندارد.

هر Question باید دارای هویت یکتا باشد.

---

تعریف Question Registration

«Question Registration فرآیندی است که طی آن، هر Question معتبر پیش از نمایش به کاربر، شناسه یکتا و اطلاعات اجرایی لازم را دریافت کرده و به‌عنوان یک موجودیت مستقل در چرخه تعامل ثبت می‌شود.»

---

هدف ثبت

این مفهوم برای پاسخ به این پرسش طراحی شده است:

«اگر بعداً بخواهیم این تعامل را تحلیل کنیم، چگونه باید بدانیم دقیقاً کدام Question مطرح شده بود؟»

---

شناسه یکتا (Question Instance ID)

هر اجرای یک Question باید شناسه مستقل داشته باشد.

نکته مهم:

شناسه اجرای Question با شناسه Template متفاوت است.

---

Question Template ID

شناسه الگوی اصلی.

---

Question Instance ID

شناسه اجرای واقعی همان Question برای یک کاربر مشخص.

---

چرا به شناسه اجرا نیاز داریم؟

ممکن است:

یک Template هزاران بار برای کاربران مختلف اجرا شود.

حتی ممکن است برای یک کاربر نیز در زمان‌های مختلف چند بار استفاده شود.

بنابراین، هر اجرا باید شناسه مستقل خود را داشته باشد.

---

اطلاعات ثبت‌شونده

ثبت هر Question معمولاً شامل اطلاعات زیر است:

- Question Instance ID
- Template ID
- Version
- Conceptها
- Goal
- Strategy
- زمان تولید
- زمان نمایش
- Context
- شناسه کاربر
- شناسه جلسه
- وضعیت اعتبارسنجی

---

ارتباط با پاسخ

هنگامی که کاربر پاسخ می‌دهد،

پاسخ هرگز مستقیماً به Template متصل نمی‌شود.

بلکه به:

Question Instance

متصل می‌شود.

این موضوع تحلیل دقیق تعامل را ممکن می‌سازد.

---

ارتباط با Book of Life

Book of Life نیز همین شناسه اجرا را ثبت می‌کند.

در نتیجه، سال‌ها بعد نیز می‌توان دقیقاً مشخص کرد:

- چه Questionی
- با چه نسخه‌ای
- در چه زمانی
- برای چه کاربری

مطرح شده است.

---

تفاوت با Log

Question Registration صرفاً ثبت رویداد نیست.

بلکه ایجاد یک موجودیت رسمی در معماری سیستم است.

Log تنها یک گزارش است.

اما Question Instance بخشی از مدل داده سیستم محسوب می‌شود.

---

مزایای ثبت

Question Registration باعث می‌شود:

- پاسخ‌ها قابل ردیابی باشند.
- تحلیل‌ها دقیق شوند.
- تعاملات بازسازی شوند.
- تاریخچه کامل باقی بماند.
- Book of Life قابل اعتماد باشد.

---

اصل معماری

بر اساس قانون اساسی TANDIL:

هر Question معتبر پیش از نمایش به کاربر باید به‌عنوان یک Question Instance مستقل ثبت شود و شناسه یکتای خود را دریافت کند تا تمام پاسخ‌ها، تحلیل‌ها، تصمیم‌ها و رویدادهای بعدی بر پایه همان شناسه انجام شوند.

این اصل تضمین می‌کند که هر تعامل انسانی در TANDIL دارای هویت مستقل، قابل ردیابی و قابل بازسازی باشد و هیچ پاسخ یا تحلیل بدون ارجاع به Question واقعی ثبت نشود.
