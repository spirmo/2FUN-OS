CHAPTER_03 — KNOWLEDGE RELATIONSHIP ARCHITECTURE

SECTION_01 — Philosophy of Relationships

PART_09 — Node ↔ Domain Relationship

در معماری TANDIL، ارتباط میان Node و Domain یکی از مهم‌ترین روابط ساختاری-اجرایی است که مرز میان «جریان اجرا» و «قلمرو دانش» را تعریف می‌کند.

این رابطه مشخص می‌کند که یک Node در کدام حوزه‌های دانشی قابل استفاده، فعال‌سازی یا محدودسازی است.

---

اصل بنیادین

Node مسئول اجرای دانش است.

Domain مسئول سازمان‌دهی حوزه‌های دانش است.

رابطه میان این دو، تعیین می‌کند:

««این جریان اجرایی در کدام قلمروهای دانشی معتبر است؟»»

---

ماهیت رابطه

Node ↔ Domain Relationship یک رابطه محدودکننده-زمینه‌ای (Contextual-Boundary Relationship) است.

در این رابطه:

- Node تغییر نمی‌کند
- Domain تغییر نمی‌کند
- فقط محدوده کاربرد Node مشخص می‌شود

---

هدف این رابطه

این رابطه برای پاسخ به این پرسش طراحی شده است:

«این Node در کدام Domainها مجاز به اجرا یا استفاده است؟»

---

نقش Node در Domain

Node می‌تواند در یک یا چند Domain قرار گیرد.

برای مثال:

- یک Node آموزشی می‌تواند در Domain «آموزش»، «روان‌شناسی» و «مدیریت» استفاده شود.
- یک Node تحلیلی می‌تواند در Domain «اقتصاد» و «حکمرانی» فعال شود.

اما Node:

- متعلق به Domain نیست
- توسط Domain کنترل نمی‌شود
- و از Domain هویت نمی‌گیرد

---

نقش Domain در Node

Domain مشخص می‌کند:

- Node در چه حوزه‌هایی معنا دارد
- در چه زمینه‌هایی فعال می‌شود
- و در چه شرایطی باید فیلتر یا محدود شود

اما Domain:

- منطق اجرایی Node را تغییر نمی‌دهد
- ترتیب اجرای Node را تعیین نمی‌کند
- و محتوای Node را تولید نمی‌کند

---

انواع ارتباط Node ↔ Domain

۱. ارتباط مجازسازی (Permission Relationship)

Domain تعیین می‌کند Node در چه حوزه‌هایی اجازه استفاده دارد.

مثال:

- Node تحلیل ریسک در Domain اقتصاد مجاز است.

---

۲. ارتباط محدودسازی (Constraint Relationship)

Domain تعیین می‌کند Node در چه حوزه‌هایی نباید اجرا شود.

مثال:

- همان Node ممکن است در Domain آموزش غیرمستقیم محدود شود.

---

۳. ارتباط زمینه‌ای (Contextual Binding)

Node در یک Domain معنای خاص پیدا می‌کند.

مثال:

- مفهوم «ریسک» در اقتصاد با «ریسک» در روان‌شناسی تفاوت کاربردی دارد.

---

۴. ارتباط چنددامنه‌ای (Multi-Domain Usage)

یک Node می‌تواند در چند Domain به‌طور هم‌زمان استفاده شود.

مثال:

- Node تصمیم‌گیری در:
  - مدیریت
  - اقتصاد
  - حکمرانی

---

استقلال دو موجودیت

Node و Domain هر دو مستقل هستند:

- Node بدون Domain وجود دارد
- Domain بدون Node وجود دارد
- هیچ‌کدام مالک دیگری نیستند

---

نقش این رابطه در معماری

این رابطه نقش کلیدی در:

- کنترل دامنه استفاده Nodeها
- جلوگیری از استفاده خارج از زمینه
- و افزایش انسجام معنایی سیستم

ایفا می‌کند.

---

تفاوت با سایر روابط

- Node ↔ Node → جریان اجرا
- Knowledge Block ↔ Node → تبدیل ساختار به اجرا
- Knowledge Unit ↔ Knowledge Block → ساختاردهی دانش
- Concept ↔ Concept → شبکه معنا
- Node ↔ Domain → کنترل زمینه کاربرد

---

Domain به‌عنوان فیلتر معنایی

Domain در این رابطه مانند یک فیلتر عمل می‌کند:

- اجازه استفاده از Node را در برخی حوزه‌ها می‌دهد
- و در برخی حوزه‌ها آن را غیرفعال می‌کند

اما این فیلتر:

- محتوا را تغییر نمی‌دهد
- و منطق Node را دست‌نخورده نگه می‌دارد

---

اصل عدم مالکیت

هیچ Domainی مالک Node نیست.

هیچ Nodeی وابسته به Domain خاصی نیست.

رابطه تنها نقش «کنترل زمینه استفاده» را دارد، نه «کنترل ساختار یا محتوا».

---

اصل معماری

بر اساس قانون اساسی TANDIL:

Nodeها در چارچوب Domainها محدود و تعریف زمینه‌ای می‌شوند، بدون آنکه هویت، منطق یا استقلال آن‌ها تغییر کند.

این رابطه تضمین می‌کند که اجرای دانش در سیستم، هم انعطاف‌پذیر و هم کنترل‌شده باقی بماند.
