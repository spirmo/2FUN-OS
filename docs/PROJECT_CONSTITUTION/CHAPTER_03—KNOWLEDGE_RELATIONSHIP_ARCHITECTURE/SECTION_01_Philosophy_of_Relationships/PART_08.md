CHAPTER_03 — KNOWLEDGE RELATIONSHIP ARCHITECTURE

SECTION_01 — Philosophy of Relationships

PART_08 — Node ↔ Node Relationship

در معماری TANDIL، یکی از حیاتی‌ترین لایه‌های شبکه دانش، ارتباط میان Nodeها است.

این رابطه تعیین می‌کند چگونه جریان اجرای دانش در سیستم حرکت می‌کند و چگونه تجربه یادگیری از یک وضعیت به وضعیت دیگر منتقل می‌شود.

---

اصل بنیادین

Node واحد اجرای دانش است.

اما هیچ Nodeی به‌صورت مستقل و ایستا معنا ندارد.

معنا و کارکرد Node تنها در ارتباط آن با Nodeهای دیگر در جریان یک مسیر شکل می‌گیرد.

---

ماهیت رابطه

Node ↔ Node Relationship یک رابطه جریانی-اجرایی (Flow-Based Relationship) است.

در این رابطه:

- Nodeها تغییر ماهیت نمی‌دهند
- محتوا تولید نمی‌شود
- تنها جریان حرکت و انتقال مشخص می‌شود

---

هدف این رابطه

این رابطه برای پاسخ به این پرسش طراحی شده است:

«پس از اجرای این Node، کدام Node باید فعال شود؟»

---

نقش Node در شبکه Nodeها

هر Node تنها یک نقطه از جریان است.

اما در ارتباط با سایر Nodeها:

- بخشی از یک مسیر یادگیری می‌شود
- یا بخشی از یک مسیر تحلیل
- یا بخشی از یک مسیر تصمیم‌گیری

---

انواع ارتباط Node ↔ Node

۱. ارتباط خطی (Linear Flow)

Nodeها به ترتیب پشت سر هم اجرا می‌شوند.

مثال:

- Node A → Node B → Node C

---

۲. ارتباط شرطی (Conditional Flow)

انتخاب Node بعدی وابسته به نتیجه Node فعلی است.

مثال:

- اگر پاسخ درست بود → Node A
- اگر غلط بود → Node B

---

۳. ارتباط انشعابی (Branching Flow)

یک Node می‌تواند چند مسیر مختلف ایجاد کند.

مثال:

- مسیر آموزشی پیشرفته
- مسیر مرور پایه
- مسیر تمرین

---

۴. ارتباط همگرایانه (Converging Flow)

چند Node مختلف به یک Node مشترک ختم می‌شوند.

مثال:

- چند مسیر آموزشی → Node تحلیل نهایی

---

۵. ارتباط بازگشتی (Recursive Flow)

Node می‌تواند به Nodeهای قبلی بازگردد.

مثال:

- تکرار آموزش
- اصلاح پاسخ
- بازبینی مفاهیم

---

استقلال Nodeها

Nodeها مستقل از یکدیگر تعریف می‌شوند.

هر Node:

- هویت مستقل دارد
- منطق اجرایی مستقل دارد
- و می‌تواند بدون وابستگی مستقیم به Node دیگر وجود داشته باشد

اما:

جریان دانش تنها از طریق ارتباط میان آن‌ها شکل می‌گیرد.

---

نقش این رابطه در معماری

Node ↔ Node Relationship ستون فقرات جریان دانش (Knowledge Flow) در TANDIL است.

این رابطه تعیین می‌کند:

- چگونه یادگیری حرکت می‌کند
- چگونه تحلیل پیش می‌رود
- و چگونه تجربه کاربر شکل می‌گیرد

---

تفاوت با سایر روابط

- Concept ↔ Concept → شبکه معنا
- Knowledge Unit ↔ Knowledge Block → ساختار دانش
- Knowledge Block ↔ Node → تبدیل دانش به اجرا
- Node ↔ Node → جریان اجرا

---

Node به‌عنوان گراف اجرایی

مجموعه Nodeها و ارتباط میان آن‌ها یک ساختار گرافی ایجاد می‌کند به نام:

«Execution Graph»

این گراف:

- مسیر یادگیری را تعریف می‌کند
- جریان تصمیم‌گیری را مشخص می‌کند
- و رفتار سیستم را قابل پیش‌بینی می‌سازد

---

اصل عدم وابستگی

هیچ Nodeی مالک Node دیگر نیست.

هیچ Nodeی بدون دلیل معماری، کنترل Node دیگر را در اختیار ندارد.

ارتباط‌ها تنها مسیر حرکت را مشخص می‌کنند، نه مالکیت یا کنترل را.

---

اصل معماری

بر اساس قانون اساسی TANDIL:

Nodeها از طریق روابط اجرایی به یک شبکه پویا تبدیل می‌شوند که جریان دانش، یادگیری و تحلیل را در سیستم شکل می‌دهد، بدون آنکه استقلال هیچ Nodeی از بین برود.

این رابطه، آخرین لایه اتصال در معماری TANDIL است و پایه شکل‌گیری تمام جریان‌های اجرایی سیستم محسوب می‌شود.
