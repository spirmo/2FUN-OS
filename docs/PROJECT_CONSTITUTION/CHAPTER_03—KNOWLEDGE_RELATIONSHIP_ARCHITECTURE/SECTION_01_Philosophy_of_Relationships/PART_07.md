CHAPTER_03 — KNOWLEDGE RELATIONSHIP ARCHITECTURE

SECTION_01 — Philosophy of Relationships

PART_07 — Knowledge Block ↔ Node Relationship

در معماری TANDIL، یکی از مهم‌ترین روابط اجرایی، ارتباط میان Knowledge Block و Node است.

این رابطه نقطه‌ای است که در آن «ساختار دانش» به «جریان اجرایی دانش» تبدیل می‌شود.

---

اصل بنیادین

Knowledge Block ساختار دانش را تعریف می‌کند.

Node اجرای دانش را مدیریت می‌کند.

رابطه میان این دو، رابطه «تبدیل ساختار به اجرا» است، نه تغییر محتوا.

---

ماهیت رابطه

Knowledge Block ↔ Node Relationship یک رابطه اجرایی-ساختاری (Execution-Structure Relationship) است.

در این رابطه:

- Knowledge Block تغییر نمی‌کند
- Node دانش جدید تولید نمی‌کند
- فقط نحوه استفاده از Knowledge Block در جریان اجرا مشخص می‌شود

---

هدف این رابطه

این رابطه برای پاسخ به این پرسش طراحی شده است:

«این Knowledge Block چگونه توسط Node اجرا یا ارائه می‌شود؟»

---

نقش Knowledge Block در Node

Knowledge Block به‌عنوان بسته ساختاری دانش وارد Node می‌شود.

Node:

- آن را در زمان مناسب فعال می‌کند
- ترتیب اجرای اجزای آن را مدیریت می‌کند
- و نحوه تعامل کاربر با آن را کنترل می‌کند

اما:

Node مالک Knowledge Block نیست.

---

نقش Node در استفاده از Knowledge Block

Node می‌تواند:

- یک Knowledge Block را نمایش دهد
- آن را به چند مرحله تقسیم کند
- یا بر اساس شرایط کاربر، نحوه اجرای آن را تغییر دهد

در همه این حالت‌ها:

Knowledge Block بدون تغییر باقی می‌ماند.

---

انواع ارتباط Knowledge Block ↔ Node

۱. ارتباط نمایشی (Rendering Relationship)

Node وظیفه نمایش Knowledge Block را بر عهده دارد.

مثال:

- نمایش یک درس یا تعریف

---

۲. ارتباط تعاملی (Interactive Relationship)

Node امکان تعامل کاربر با Knowledge Block را فراهم می‌کند.

مثال:

- پاسخ دادن به سؤال
- انتخاب گزینه
- دریافت بازخورد

---

۳. ارتباط مرحله‌ای (Stepwise Execution)

Knowledge Block در چند Node متوالی اجرا می‌شود.

مثال:

- آموزش مرحله‌به‌مرحله یک مفهوم

---

۴. ارتباط شرطی (Conditional Execution)

اجرای Knowledge Block وابسته به شرایط کاربر یا نتیجه قبلی است.

مثال:

- اگر پاسخ درست بود → Node بعدی
- اگر غلط بود → تکرار یا مسیر جایگزین

---

استقلال دو موجودیت

Knowledge Block و Node هر دو مستقل هستند:

- Knowledge Block بدون Node وجود دارد
- Node بدون Knowledge Block نیز می‌تواند برای عملیات سیستمی وجود داشته باشد
- هیچ‌کدام مالک دیگری نیستند

---

نقش این رابطه در معماری

این رابطه آخرین مرحله تبدیل دانش از حالت ساختاری به حالت اجرایی است.

در این نقطه:

«دانش از «ساختار» وارد «تجربه» می‌شود.»

---

Node به‌عنوان لایه اجرا

Node تعیین می‌کند:

- چه زمانی دانش فعال شود
- چگونه ارائه شود
- و چگونه با کاربر تعامل کند

اما محتوا را تغییر نمی‌دهد.

---

اصل عدم وابستگی

Node هیچ Knowledge Blockی را تولید یا تغییر نمی‌دهد.

Knowledge Block نیز وابسته به هیچ Node خاصی نیست.

رابطه تنها نقش «تبدیل و اجرا» را دارد، نه «مالکیت» یا «تولید».

---

اصل معماری

بر اساس قانون اساسی TANDIL:

Knowledge Block ساختار دانش را تعریف می‌کند و Node آن ساختار را به تجربه اجرایی تبدیل می‌کند، بدون آنکه در محتوای یکدیگر دخالت داشته باشند.

این رابطه، پل نهایی میان «دانش سازمان‌یافته» و «تجربه زنده دانش» در معماری TANDIL است.
