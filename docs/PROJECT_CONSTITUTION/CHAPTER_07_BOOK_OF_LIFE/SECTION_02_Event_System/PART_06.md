CHAPTER_07 — BOOK OF LIFE

SECTION_02 — Event System

PART_06 — ارتباط Event با Signal

Event کوچک‌ترین واحد ثبت رخداد است.

اما Event به‌تنهایی برای تحلیل کافی نیست.

سیستم باید بتواند از روی مجموعه‌ای از Eventها، معنا استخراج کند.

این وظیفه بر عهده Signal Layer است.

بنابراین، رابطه میان Event و Signal یکی از مهم‌ترین ارتباط‌های معماری TANDIL محسوب می‌شود.

---

اصل بنیادین

Event ثبت می‌شود.

Signal تحلیل می‌شود.

---

تعریف ارتباط

«Signal نتیجه تحلیل یک یا چند Event است و به‌عنوان لایه واسط میان ثبت رخدادها و به‌روزرسانی مدل‌های شناختی در معماری TANDIL عمل می‌کند.»

---

هدف این طراحی

این مفهوم برای پاسخ به این پرسش طراحی شده است:

«چگونه از Eventهای خام، اطلاعات قابل استفاده برای Human Model تولید می‌شود؟»

---

Event به‌تنهایی کافی نیست

فرض کنید کاربر تنها یک پاسخ ثبت کرده است.

این پاسخ به‌تنهایی نمی‌تواند نشان دهد:

- آیا یادگیری اتفاق افتاده است؟
- آیا استدلال بهبود یافته است؟
- آیا رشد رخ داده است؟

Event فقط وقوع یک عمل را ثبت می‌کند.

---

نقش Signal

Signal با تحلیل Eventها مشخص می‌کند:

- چه تغییری رخ داده است؟
- شدت تغییر چقدر است؟
- این تغییر به کدام Profile مربوط است؟
- میزان اطمینان تحلیل چقدر است؟

---

رابطه یک‌به‌چند

یک Event ممکن است:

- هیچ Signalی تولید نکند.
- یک Signal تولید کند.
- چندین Signal مختلف تولید کند.

برای مثال:

ثبت یک پاسخ ممکن است هم‌زمان:

- Concept Signal
- Reasoning Signal
- Learning Signal

ایجاد کند.

---

رابطه چند‌به‌یک

گاهی نیز:

چندین Event مختلف،

پس از تحلیل،

تنها یک Signal معتبر تولید می‌کنند.

برای مثال:

ده‌ها تعامل کوچک ممکن است در نهایت فقط یک تغییر معنادار در Interaction Profile ایجاد کنند.

---

جریان معماری

Event
   ↓
Signal Analysis Engine
   ↓
Signal
   ↓
Human Model

---

استقلال Event

Event هرگز تغییر نمی‌کند.

اگر تحلیل‌های آینده تغییر کنند،

Signal جدید تولید می‌شود،

نه اینکه Event اصلاح شود.

---

مزایای این طراحی

این معماری باعث می‌شود:

- داده خام از تحلیل جدا شود.
- تحلیل‌ها قابل توسعه باشند.
- الگوریتم‌های آینده بدون تغییر Book of Life بهبود یابند.
- Explainability حفظ شود.

---

ارتباط با Explainability

هر Signal باید بتواند مشخص کند:

از کدام Eventها ایجاد شده است.

بنابراین مسیر تحلیل همیشه قابل بازسازی خواهد بود.

---

نگاه فلسفی

در TANDIL:

رخدادها حقیقت خام هستند.

Signalها، فهم معماری‌شده از آن حقیقت‌اند.

این دو نباید با یکدیگر اشتباه گرفته شوند.

---

اصل معماری

بر اساس قانون اساسی TANDIL:

Event و Signal باید دو لایه مستقل در معماری TANDIL باشند؛ Event مسئول ثبت تغییرناپذیر رخدادهای واقعی است و Signal مسئول تحلیل و استخراج معنا از یک یا چند Event. هیچ تغییری در تحلیل نباید باعث تغییر Event شود و تمام ارتباط میان این دو باید به‌صورت کامل قابل ردیابی و قابل بازسازی باشد.

این اصل تضمین می‌کند که داده‌های خام و تحلیل‌های حاصل از آن‌ها همیشه از یکدیگر مستقل باقی بمانند و سیستم بتواند بدون از دست دادن تاریخچه واقعی، روش‌های تحلیل خود را در آینده توسعه دهد.
