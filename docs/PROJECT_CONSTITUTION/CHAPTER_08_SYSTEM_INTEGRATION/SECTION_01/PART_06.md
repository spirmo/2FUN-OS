CHAPTER_08 — SYSTEM INTEGRATION

SECTION_01 — چرا معماری به لایه یکپارچه‌سازی نیاز دارد؟

PART_06 — جمع‌بندی نهایی System Integration

در این بخش، لایه System Integration به‌عنوان ستون هماهنگ‌کننده معماری TANDIL تعریف شد.

هدف این لایه ایجاد وابستگی میان اجزا نیست.

هدف، ایجاد همکاری قانون‌مند میان اجزای مستقل سامانه است.

---

جایگاه System Integration

در معماری TANDIL:

- هر موتور مسئول انجام وظیفه خود است.
- هیچ موتور مالک کل سامانه نیست.
- همکاری میان موتورها تنها از طریق قوانین معماری انجام می‌شود.

System Integration همین قوانین را تعریف و تضمین می‌کند.

---

آنچه در این بخش تثبیت شد

System Integration:

- مسئول هماهنگی میان موتورها است.
- جریان استاندارد اطلاعات را تعریف می‌کند.
- مرز مسئولیت هر موتور را مشخص می‌کند.
- وابستگی‌های معماری را کنترل می‌کند.
- الگوی ارتباط میان موتورها را استاندارد می‌سازد.
- از استقلال عملکردی اجزا محافظت می‌کند.

---

آنچه System Integration نیست

System Integration:

- موتور تحلیل نیست.
- پایگاه داده نیست.
- موتور تصمیم‌گیری نیست.
- مالک حقیقت نیست.

او تنها چارچوب همکاری میان اجزای سامانه را تعیین می‌کند.

دستاورد این فصل

با پایان این بخش مشخص شد:

- هر موتور چه مسئولیتی دارد.
- اطلاعات چگونه میان موتورها حرکت می‌کنند.
- وابستگی‌ها چگونه کنترل می‌شوند.
- تعاملات چگونه استاندارد می‌شوند.

در نتیجه، اجزای مستقل TANDIL به یک سامانه واحد و منسجم تبدیل شدند.

---

جمع‌بندی فلسفی

در TANDIL:

قدرت معماری در تعداد موتورهای آن نیست.

قدرت واقعی در نظم تعامل میان آن‌هاست.

System Integration نگهبان این نظم است.

---

اصل معماری نهایی

بر اساس قانون اساسی TANDIL:

System Integration باید به‌عنوان لایه هماهنگ‌کننده معماری TANDIL عمل کرده و با تعریف مرزهای مسئولیت، جریان استاندارد اطلاعات، Interfaceهای مشترک و الگوهای ارتباطی، همکاری میان تمامی اجزای سامانه را تضمین نماید، بدون آنکه استقلال عملکردی یا مالکیت داده‌های هر موتور را نقض کند.

این اصل تضمین می‌کند که معماری TANDIL در تمام مراحل توسعه، یکپارچه، پایدار، توسعه‌پذیر و قابل ممیزی باقی بماند.
