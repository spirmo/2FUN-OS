# KPS Document Production Rules
## قوانین تولید مستندات KPS

**Version:** 1.0

**Status:** ARCHITECTURE LAW

---

# هدف (Purpose)

این سند قوانین استاندارد تولید تمامی فرم‌ها، کاربرگ‌ها، قالب‌ها و بسته‌های دانشی (Knowledge Packages / بسته‌های دانشی) در سامانه KPS را تعریف می‌کند.

تمام ابزارهای تولید دانش در پروژه TANDIL موظف به رعایت این قوانین هستند.

---

# قانون ۱ — اصل فرم خودآموز (Self-Teaching Form Principle)

هر فرم باید به گونه‌ای طراحی شود که بدون نیاز به مطالعه مستندات خارجی، توسط یک توسعه‌دهنده جدید قابل تکمیل باشد.

فرم باید خود، نقش راهنما را ایفا کند.

---

# قانون ۲ — عنوان‌های دو‌زبانه (Bilingual Titles / عنوان‌های دو‌زبانه)

تمام فیلدها باید دارای عنوان دو‌زبانه باشند.

الگوی استاندارد:

```
English Title (عنوان فارسی)
```

نمونه:

- Canonical Name (نام استاندارد کانسپت)
- Definition (تعریف)
- Evidence (شاهد)
- Relationship (رابطه)
- Metadata (فراداده)

---

# قانون ۳ — راهنمای ورودی (Placeholder / متن راهنمای کم‌رنگ)

هر فیلد باید دارای Placeholder آموزشی باشد.

Placeholder باید:

- توضیح دهد چه اطلاعاتی باید وارد شود.
- مشخص کند چه اطلاعاتی نباید وارد شود.
- حداقل یک مثال واقعی ارائه کند.

Placeholder نباید صرفاً شامل یک کلمه یا مثال کوتاه باشد.

---

# قانون ۴ — راهنمای آموزشی (Tooltip / Help / راهنمای آموزشی)

هر فیلد باید دارای بخش راهنمای آموزشی باشد.

این راهنما باید:

- هدف وجود فیلد را توضیح دهد.
- ارتباط آن با سایر بخش‌ها را بیان کند.
- خطاهای رایج را توضیح دهد.
- بهترین روش تکمیل آن را آموزش دهد.

---

# قانون ۵ — آموزش درون فرم (Embedded Guidance / آموزش درون فرم)

تمام آموزش‌های موردنیاز باید داخل خود فرم وجود داشته باشند.

کاربر نباید برای تکمیل فرم مجبور به مراجعه به فایل یا مستند دیگری شود.

---

# قانون ۶ — سادگی (Simplicity / سادگی)

فرم باید فقط اطلاعات موردنیاز را درخواست کند.

از نمایش اطلاعات فنی، شناسه‌های داخلی یا جزئیات معماری به توسعه‌دهنده خودداری شود.

---

# قانون ۷ — جداسازی آموزش از داده (Separation of Guidance from Data / جداسازی آموزش از داده)

تمام Placeholderها و Tooltipها صرفاً برای آموزش هستند.

این اطلاعات:

- ذخیره نمی‌شوند.
- چاپ نمی‌شوند.
- جزئی از داده نهایی محسوب نمی‌شوند.

---

# قانون ۸ — منبع واحد حقیقت (Single Source of Truth / منبع واحد حقیقت)

راهنماهای موجود در فرم، مرجع رسمی نحوه تکمیل آن هستند.

تمام ابزارهای پروژه، از جمله هوش مصنوعی، باید همین راهنماها را به عنوان مرجع واحد استفاده کنند.

---

# قانون ۹ — تجربه توسعه‌دهنده (Developer Experience / تجربه توسعه‌دهنده)

طراحی فرم باید به گونه‌ای باشد که:

- یادگیری را ساده کند.
- خطاهای ورود اطلاعات را کاهش دهد.
- سرعت تولید دانش را افزایش دهد.
- کیفیت داده‌های تولیدشده را بهبود بخشد.

---

# نتیجه (Conclusion / نتیجه)

در پروژه TANDIL، فرم‌های KPS صرفاً ابزار ورود اطلاعات نیستند.

آن‌ها بخشی از فرآیند آموزش، استانداردسازی و تولید دانش محسوب می‌شوند.

هر فرم باید بتواند توسعه‌دهنده را از آغاز تا پایان فرآیند تولید دانش هدایت کند، بدون آنکه نیاز به مستندات جانبی داشته باشد.

این سند از لحظه تصویب، برای تمامی فرم‌ها، قالب‌ها، کاربرگ‌ها و ابزارهای تولید دانش در پروژه TANDIL لازم‌الاجرا است.
