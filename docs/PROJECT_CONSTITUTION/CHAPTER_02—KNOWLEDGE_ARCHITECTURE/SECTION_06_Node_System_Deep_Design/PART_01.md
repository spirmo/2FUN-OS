CHAPTER_02 — KNOWLEDGE ARCHITECTURE

SECTION_06 — Node System Deep Design

PART_01 — فلسفه وجود Node

در معماری TANDIL، پس از تعریف لایه‌های Concept، Knowledge Unit و Knowledge Block، یک نیاز بنیادی در سیستم آشکار می‌شود:

چگونه دانش باید در قالب مسیر، جریان و تجربه اجرایی به کار گرفته شود؟

وجود دانش به‌تنهایی کافی نیست.
سازمان‌دهی دانش نیز به‌تنهایی کافی نیست.

سیستم برای تبدیل دانش به تجربه قابل استفاده، نیاز به یک لایه «جریان‌دهنده» دارد.

این لایه همان Node System است.

---

مسئله اصلی

اگر Knowledge Block ساختار دانش را فراهم می‌کند، سؤال مهم این است:

چه چیزی تعیین می‌کند که این ساختار دانش در چه لحظه، برای چه کاربر، و در چه ترتیب فعال شود؟

بدون وجود چنین لایه‌ای:

- دانش به‌صورت ایستا باقی می‌ماند
- ترتیب یادگیری نامشخص می‌شود
- مسیر رشد کاربر قابل کنترل نیست
- و سیستم نمی‌تواند تجربه یادگیری طراحی کند

---

فلسفه طراحی Node

Node برای حل این شکاف ایجاد شد:

«فاصله میان «دانش موجود» و «دانش در حال استفاده»»

Node لایه‌ای است که دانش را از حالت ایستا خارج کرده و آن را وارد حالت جریان (Flow) می‌کند.

---

Node به‌عنوان لایه حرکت

در حالی که Knowledge Block ساختار دانش را تعریف می‌کند، Node تعریف می‌کند:

- چه چیزی در چه زمانی نمایش داده شود
- چه مفاهیمی پشت سر هم فعال شوند
- مسیر حرکت ذهنی کاربر چگونه شکل بگیرد
- و تجربه یادگیری چگونه جریان پیدا کند

---

جایگاه Node در معماری

Node در نقطه اتصال بین «دانش» و «تجربه» قرار دارد.

- Concept → تعریف حقیقت
- Knowledge Unit → واحد دانش
- Knowledge Block → ساختار دانش
- Node → جریان دانش
- Domain → مرز کاربرد دانش

---

تفاوت بنیادین فلسفی

Knowledge Block می‌گوید:
«چه چیزهایی باید با هم دیده شوند»

Node می‌گوید:
«چه چیزی باید بعد از چه چیزی دیده شود»

---

نتیجه اولیه

Node اولین لایه‌ای است که در آن:

- دانش از حالت ایستا خارج می‌شود
- و وارد حالت تجربه زمانی و ترتیبی می‌شود

به همین دلیل، Node را می‌توان «لایه حرکت دانش» در معماری TANDIL دانست.

---

اصل معماری

بر اساس قانون اساسی TANDIL:

Node، دانش را در زمان و ترتیب فعال می‌کند.

این لایه پایه‌ای‌ترین عنصر برای تبدیل دانش به تجربه یادگیری و مسیر رشد در کل سیستم محسوب می‌شود.
