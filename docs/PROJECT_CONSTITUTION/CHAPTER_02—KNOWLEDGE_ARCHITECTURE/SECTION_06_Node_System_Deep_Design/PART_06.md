PART_06 — انواع Node در معماری TANDIL

Node در معماری TANDIL یک موجودیت عمومی است، اما تمام Nodeها وظیفه یکسانی ندارند.

بسته به نقش آن‌ها در جریان یادگیری، تحلیل یا اجرای سیستم، Nodeها می‌توانند انواع مختلفی داشته باشند.

این تقسیم‌بندی باعث می‌شود که سیستم بتواند بدون تغییر در ساختار اصلی Node، رفتارهای متفاوتی را پیاده‌سازی کند.

---

اصل بنیادین

تمام Nodeها از یک معماری مشترک پیروی می‌کنند.

تفاوت آن‌ها در نقش اجرایی است، نه در هویت معماری.

بنابراین، «نوع Node» یک ویژگی عملکردی است، نه یک موجودیت جدید.

---

۱. Learning Node

Learning Node برای انتقال دانش و هدایت فرآیند یادگیری طراحی می‌شود.

وظایف اصلی:

- ارائه Knowledge Block
- ایجاد مسیر آموزشی
- آماده‌سازی برای مرحله بعد

---

۲. Assessment Node

Assessment Node برای ارزیابی میزان یادگیری یا درک کاربر استفاده می‌شود.

وظایف اصلی:

- سنجش فهم
- تحلیل پاسخ‌ها
- تصمیم‌گیری درباره ادامه مسیر

---

۳. Decision Node

Decision Node مسئول انتخاب مسیر بعدی بر اساس شرایط موجود است.

این Node ممکن است بر اساس:

- نتایج ارزیابی
- وضعیت کاربر
- قوانین سیستم
- یا سیاست‌های اجرایی

مسیر مناسب را انتخاب کند.

---

۴. Interaction Node

Interaction Node برای ایجاد تعامل مستقیم با کاربر طراحی می‌شود.

نمونه‌ها:

- پرسیدن سؤال
- دریافت بازخورد
- ثبت تصمیم
- آغاز یک گفت‌وگو

---

۵. Analysis Node

Analysis Node داده‌های موجود را تحلیل می‌کند تا نتیجه‌ای برای ادامه مسیر یا تولید بینش فراهم شود.

این نوع Node بیشتر در موتورهای تحلیل و همزاد دیجیتال کاربرد دارد.

---

۶. System Node

System Node مستقیماً با کاربر تعامل ندارد.

وظیفه آن انجام عملیات داخلی سیستم است، مانند:

- همگام‌سازی داده‌ها
- اعتبارسنجی
- اجرای قوانین
- کنترل وضعیت

---

قابلیت توسعه

فهرست انواع Nodeها بسته نیست.

در آینده، معماری TANDIL می‌تواند انواع جدیدی از Node را معرفی کند، مشروط بر اینکه:

- با اصول بنیادین Node سازگار باشند.
- نقش اجرایی مشخصی داشته باشند.
- قوانین معماری را نقض نکنند.

---

اصل معماری

تمام انواع Nodeها دارای یک هویت مشترک هستند.

آنچه آن‌ها را از یکدیگر متمایز می‌کند، نقش آن‌ها در اجرای جریان دانش است، نه ساختار بنیادی آن‌ها.

به همین دلیل، در معماری TANDIL، «نوع Node» یک ویژگی اجرایی است و نه یک لایه مستقل از معماری.
