CHAPTER_02 — KNOWLEDGE ARCHITECTURE

SECTION_06 — Node System Deep Design

PART_07 — مدل اجرایی (Execution Model) در Node

Node در معماری TANDIL صرفاً یک نقطه ایستا در مسیر یادگیری نیست.

هر Node دارای یک مدل اجرایی (Execution Model) است که مشخص می‌کند چگونه وارد چرخه اجرا شود، چگونه وظیفه خود را انجام دهد و تحت چه شرایطی مسیر را به Node بعدی منتقل کند.

---

هدف مدل اجرایی

مدل اجرایی برای پاسخ به این پرسش طراحی شده است:

«یک Node چگونه رفتار می‌کند؟»

نه اینکه چه دانشی دارد، بلکه چگونه آن دانش را در جریان سیستم به کار می‌گیرد.

---

مراحل اجرای یک Node

هر Node، صرف‌نظر از نوع آن، به‌صورت کلی چرخه زیر را طی می‌کند:

مرحله ۱ — فعال‌سازی (Activation)

Node زمانی فعال می‌شود که شرایط ورود آن برقرار باشد.

این شرایط می‌تواند شامل موارد زیر باشد:

- تکمیل Node قبلی
- رسیدن کاربر به یک مرحله مشخص
- وقوع یک رویداد
- یا اجرای یک قانون سیستمی

---

مرحله ۲ — آماده‌سازی (Preparation)

پس از فعال شدن، Node منابع موردنیاز خود را آماده می‌کند.

برای مثال:

- بارگذاری Knowledge Blockها
- بررسی وضعیت کاربر
- دریافت داده‌های لازم
- آماده‌سازی محیط اجرا

---

مرحله ۳ — اجرا (Execution)

در این مرحله، مأموریت اصلی Node انجام می‌شود.

بسته به نوع Node، این اجرا ممکن است شامل:

- نمایش محتوا
- دریافت پاسخ
- تحلیل داده
- اجرای یک قانون
- یا تصمیم‌گیری درباره ادامه مسیر

باشد.

---

مرحله ۴ — ارزیابی (Evaluation)

پس از پایان اجرا، Node نتیجه عملیات خود را ارزیابی می‌کند.

این ارزیابی مشخص می‌کند:

- آیا هدف Node محقق شده است؟
- آیا شرایط عبور فراهم است؟
- آیا نیاز به تکرار وجود دارد؟
- آیا باید مسیر تغییر کند؟

---

مرحله ۵ — انتقال (Transition)

در صورت موفقیت، Node کنترل را به Node بعدی منتقل می‌کند.

این انتقال ممکن است:

- خطی باشد.
- شرطی باشد.
- یا بر اساس تصمیم موتور مسیر انجام شود.

---

استقلال مدل اجرا

مدل اجرایی مستقل از محتوای دانش است.

یعنی:

دو Node می‌توانند دقیقاً از یک Knowledge Block استفاده کنند، اما مدل اجرایی متفاوتی داشته باشند.

برای مثال:

- یک Node ممکن است همان Knowledge Block را به‌صورت آموزشی ارائه کند.
- Node دیگر همان Knowledge Block را به‌عنوان آزمون یا تحلیل مورد استفاده قرار دهد.

---

اصل معماری

مدل اجرایی بخشی از Node است، نه بخشی از Knowledge Block.

Knowledge Block مشخص می‌کند چه دانشی وجود دارد.

Execution Model مشخص می‌کند آن دانش چگونه اجرا شود.

---

نتیجه

بر اساس قانون اساسی TANDIL:

Node دارای یک چرخه اجرایی استاندارد است که شامل فعال‌سازی، آماده‌سازی، اجرا، ارزیابی و انتقال می‌شود.

این مدل اجرایی، رفتار تمام Nodeهای سیستم را یکپارچه و قابل پیش‌بینی می‌کند و زمینه لازم را برای توسعه، نگهداری و مقیاس‌پذیری معماری فراهم می‌سازد.
